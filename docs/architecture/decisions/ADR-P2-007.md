# ADR-P2-007 — Segurança, Docker e Kubernetes local

- **Status:** Aceito — com Docker Desktop Kubernetes no lugar de Kind.

## Decisão
- UsersAPI emite JWT simétrico; CatalogAPI valida assinatura, issuer, audience e expiração; autorização adequada aos endpoints.
- Senhas com hash seguro; credenciais PostgreSQL/RabbitMQ e chave JWT fora do Git.
- .NET 8, Dockerfile multi-stage e `.dockerignore` por serviço, runtime mínimo, execução não privilegiada quando compatível.
- **Docker Desktop Kubernetes** como cluster local de referência; documentar habilitação e contexto `docker-desktop`.
- Cada serviço mantém `/k8s` na raiz com Deployment, Service, ConfigMap e referências a Secret. O repositório de infraestrutura coordena recursos compartilhados e implantação.
- ConfigMaps para configuração não sensível; Secrets criados localmente para segredos. Somente exemplos sem valores reais versionados.
- PostgreSQL com volume no Compose e PVC no Kubernetes. Health checks, probes e logs estruturados; recursos ajustados ao ambiente local.
- Compose deve iniciar serviços e dependências; documentar `docker compose up --build` e compatibilidade `docker-compose up` quando instalado.
- AKS, ECS, HPA e stack completa de observabilidade não são obrigatórios.

## Verificação
`kubectl config use-context docker-desktop`, `kubectl get nodes`, imagens disponíveis ao cluster, aplicação dos manifestos e `kubectl get deployments,pods,services`. Testar fluxos, Secrets e persistência. Não usar comandos Kind.
